# 키친포스

## 퀵 스타트

```sh
cd docker
docker compose -p kitchenpos up -d
```

## 요구 사항
### 메뉴 (Menu)
- **등록 및 조회**
    - [ ] 메뉴를 등록할 수 있다.
        - [ ] 메뉴 생성 시 필요한 요소
            - [ ] 메뉴 구성 상품과 메뉴 그룹이 존재해야 한다.
            - [ ] 메뉴 생성 시 메뉴 그룹이 존재하지 않으면 예외가 발생한다.
            - [ ] 메뉴 생성 시 메뉴 상품이 존재하지 않으면 예외가 발생한다.
            - [ ] 메뉴와 연결된 상품이 실제로 존재하지 않으면 예외가 발생한다.
            - [ ] 메뉴명에는 비속어가 포함될 수 없다.
    - [ ] 전체 메뉴를 조회할 수 있다.

- **가격 및 노출여부**
    - [ ] 메뉴의 가격을 수정할 수 있다.
        - [ ] 메뉴의 가격은 0원 이상의 null이 아닌 수이어야 한다.
        - [ ] 실제 판매 가격(메뉴 가격)이 상품 원가 총합보다 클 경우에만 메뉴를 활성화한다.
    - [ ] 메뉴의 노출 여부를 변경할 수 있다.

- **메뉴 그룹**
    - [ ] 메뉴는 하나 이상의 메뉴 그룹으로 등록할 수 있다.
    - [ ] 메뉴 그룹을 등록할 수 있다.
    - [ ] 전체 메뉴 그룹을 조회할 수 있다.
        - [ ] 메뉴 그룹명은 빈 문자열이거나 null일 수 없다.

### 메뉴 상품 (Menu Product)
- [ ] 메뉴와 상품 간의 수량을 등록할 수 있다.
- [ ] 메뉴는 1개 이상의 상품을 포함한다.

### 상품 (Product)
- **등록 및 조회**
    - [ ] 상품을 등록할 수 있다.
    - [ ] 전체 상품을 조회할 수 있다.

- **속성 관리**
    - [ ] 상품의 가격을 수정할 수 있다.
        - [ ] 상품의 가격은 0원 이상이어야 한다.
    - [ ] 상품명은 빈 문자열이거나 null일 수 없다.
    - [ ] 상품명에는 비속어가 포함될 수 없다.

### 주문 (Order)
- **등록 및 조회**
    - [ ] 주문을 등록할 수 있다.
        - [ ] 필수값 및 상태
            - [ ] 주문 등록 시 주문의 상태는 WAITING이다.
            - [ ] 주문 등록 시 주문의 타입은 필수값이다.
            - [ ] 주문 등록 시 주문 내역이 null이거나 empty이면 예외가 발생한다.
            - [ ] 주문 등록 시 주문 내역에 해당하는 메뉴가 존재하지 않으면 예외가 발생한다.
            - [ ] 주문 등록 시 주문 타입이 EAT_IN이 아닌 경우 수량은 0이상이어야 한다.
            - [ ] 주문 등록 시 주문 내역의 메뉴 가격과 실제 메뉴 가격이 다르면 예외가 발생한다.
    - [ ] 주문을 조회할 수 있다.

- **주문 상태 변경**
    - **WAITING 상태**
        - [ ] 주문 승인 시 주문 상태가 ACCEPTED로 변경된다.
        - [ ] 주문 승인 시 기존 주문의 상태가 WAITING이 아닌 경우 예외가 발생한다.
        - [ ] 주문 승인 시 주문 타입이 DELIVERY인 경우 주소값이 null이면 예외가 발생한다.
        - [ ] 주문 승인 시 주문 타입이 DELIVERY인 경우 라이더에 배달 요청을 한다.
    - **ACCEPTED 상태**
        - [ ] 주문 제공 시 주문 상태가 SERVED로 변경된다.
        - [ ] 주문 제공 시 기존 주문의 상태가 ACCEPTED가 아닌 경우 예외가 발생한다.
    - **DELIVERING 상태**
        - [ ] 주문의 배달 시작 시 기존 주문의 타입이 DELIVERY가 아닌 경우 예외가 발생한다.
        - [ ] 주문의 배달 시작 시 기존 주문 상태가 ACCEPTED가 아닌 경우 예외가 발생한다.
        - [ ] 주문의 배달 시작 시 주문 상태가 DELIVERING로 변경된다.
    - **DELIVERED 상태**
        - [ ] 주문의 배달 완료 시 기존 주문의 상태가 DELIVERING이 아닌 경우 예외가 발생한다.
        - [ ] 주문의 배달 완료 시 주문 상태가 DELIVERED로 변경된다.
    - **COMPLETED 상태**
        - [ ] 주문의 완료 시 주문 타입이 DELIVERY인 경우 상태가 DELIVERED가 아니면 예외가 발생한다.
        - [ ] 주문의 완료 시 주문 타입이 TAKE_OUT이거나 EAT_IN인 경우, 상태가 SERVED가 아니면 예외가 발생한다.
        - [ ] 주문의 완료 시 주문 상태가 COMPLETED로 변경된다.
        - [ ] 주문의 완료 시 주문 타입이 EAT_IN인 경우 주문 테이블을 빈 테이블로 변경한다.

- **주문 타입 및 속성**
    - [ ] 주문은 DELIVERY, TAKEOUT, EAT_IN 타입을 갖는다.
    - [ ] 주문은 하나 이상의 주문 내역에 포함된다.
    - [ ] 주문은 WAITING, ACCEPTED, SERVED, DELIVERING, DELIVERED, COMPLETED 상태를 갖는다.
    - [ ] 주문은 상태 및 타입에 따라 주소값이 null일 수 있다.
    - [ ] 주문 타입이 DELIVERY인 경우 주소값은 필수값이다.
    - [ ] 주문 타입이 EAT_IN인 경우 주문 테이블은 필수값이다.
    - [ ] 주문 타입이 EAT_IN인 경우 주문 테이블은 빈 테이블만 이용할 수 있다.

### 주문 테이블 (Order Table)
- **등록 및 조회**
    - [ ] 주문 테이블을 등록할 수 있다.
    - [ ] 전체 주문 테이블을 조회할 수 있다.

- **상태 및 속성 관리**
    - [ ] 주문 테이블의 이용 여부를 수정할 수 있다.
    - [ ] 주문 테이블의 이용 인원을 수정할 수 있다.
    - [ ] 빈 테이블만 이용할 수 있다.
    - [ ] 주문 테이블 명은 빈 문자열이거나 null일 수 없다.
    - [ ] 주문 테이블이 할당되면 이용 여부를 true로 변경한다.
    - [ ] 주문 테이블이 이용완료되면 빈 테이블로 변경한다.
    - [ ] 주문 테이블의 이용 인원은 0명 이상이어야 한다.
