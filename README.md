# 도메인 주도 설계 이해

## STEP 2 - Kitchen pos 요구사항

### 요구 사항

키친POS는 레스토랑의 주문과 메뉴를 관리하는 시스템입니다.

## 요구사항

### 메뉴
- 메뉴를 등록한다.
  - [ ] 메뉴 가격은 0원 이상이어야 한다.
  - [ ] 메뉴는 메뉴 그룹에 속해야 한다.
  - [ ] 메뉴는 1개 이상의 상품으로 구성된다.
  - [ ] 메뉴 생성 시 지정된 모든 상품이 실제로 데이터베이스에 존재해야 한다.
  - [ ] 메뉴 상품 수량은 0개 이상이어야 한다.
  - [ ] 메뉴 가격의 합이 구성 상품의 가격 총합보다 큰 경우 등록할 수 없다.
  - [ ] 메뉴 이름에는 비속어가 포함될 수 없다 (profanity).
- 메뉴를 수정한다.
  - 메뉴 가격을 변경할 수 있다
    - [ ] 메뉴 가격은 0원 이상이어야 한다
    - [ ] 메뉴 가격의 합이 구성 상품의 가격 총합보다 큰 경우 수정할 수 없다.
  - 메뉴 노출 상태 변경
    [ ] 메뉴를 노출(display) 상태로 변경할 수 있다.
      - 메뉴의 실제 가격이 구성 상품들의 총 가격보다 크면 노출 할 수 없다
      - 메뉴의 실제 가격이 구성 상품들의 총 가격보다 작거나 같으면 노출 할 수 있다 
    - [ ] 메뉴를 숨김(hide) 상태로 변경할 수 있다.
      - 메뉴가 존재 하지 않는 경우 숨김 상태로 변경할 수 없다
- 메뉴를 조회한다.
  - [ ] 메뉴를 조회할 수 있다

### 메뉴 그룹
- 메뉴 그룹을 등록한다.
  - [ ] 메뉴 그룹 이름은 필수이다.
-  메뉴 그룹을 조회한다.
  - [ ] 메뉴 그룹을 조회할 수 있다.

### 상품
- 상품을 등록한다.
  - [ ] 상품 가격은 0원 이상이어야 한다.
  - [ ] 상품 이름에는 비속어가 포함될 수 없다 (profanity).
- 상품을 가격을 수정한다.
  - [ ] 상품 가격은 있어야 하고, 0원 이상이어야 한다.
  - [ ] 메뉴 가격이 상품의 합산 가격보다 클때. 노출을 해제한다.
- [ ] 상품을 조회한다.
  

### 주문 
- 주문을 생성한다.
  - [ ] 주문은 반드시 주문 유형을 가지고 있어야 한다 (DELIVERY, TAKEOUT, EAT_IN).
  - [ ] 주문은 한 개 이상의 주문 상품을 가지고 있어야 한다.
  - [ ] 주문 항목의 메뉴는 실제로 존재해야 한다.
  - [ ] 매장 식사가 아닌 경우에는 수량이 음수일 수 없다.
    - 매장식사의 경우는 음수수량을 허용(?)한다.
  - [ ] 메뉴가 존재하고, 노출 상태인 경우에만 주문할 수 있다.
  - [ ] 요청된 주문 가격이 메뉴 가격과 일치해야 한다.
- 주문 상태 관리
  - 주문을 접수한다.
    - [ ] 대기(WAITING) 상태의 주문만 접수할 수 있다.
    - [ ] 배달 주문(DELIVERY)의 경우 배달 서비스에 배달 요청을 한다.
    - [ ] 주문 접수 시 주문 상태는 접수(ACCEPTED)로 변경된다.
  - 주문을 서빙한다.
    - [ ] 주문 상태가 접수(ACCEPTED)인 주문만 서빙할 수 있다.
    - [ ] 주문 서빙 시 주문 상태는 서빙(SERVED)로 변경된다.
  - 주문을 배달한다.
    - [ ] 배달 주문만 배달할 수 있다.
    - [ ] 주문 배달 시 주문 상태는 배달(DELIVERING)로 변경된다.
  - 배달을 완료한다.
    - [ ] 주문 상태가 배달 중(DELIVERING)인 주문만 배달 완료(DELIVERED)할 수 있다.
  - 주문을 완료한다.
    - [ ] 주문 타입이 배달(DELIVERY)인 경우, 주문 상태가 배달 완료(DELIVERED)된 주문만 완료할 수 있다.
    - [ ] 주문 타입이 매장식사(EAT_IN)와 테이크아웃(TAKEOUT)인 경우 주문 상태가 서빙 완료(SERVED)인 경우만 완료할 수 있다.
    - [ ] 매장식사 주문이 완료되면 해당 테이블의 주문이 모두 완료된 경우 테이블을 초기화한다
- [ ] 상품을 조회한다.
  
### 주문 테이블
- 주문 테이블을 등록한다.
  - [ ] 주문 테이블은 테이블 이름을 가지고 있어야 한다.
  - [ ] 새로운 주문 테이블은 UUID 형식의 고유 식별자를 가지고 있어야 한다.
  - [ ] 초기 손님 수는 0명으로 설정하고, 주문 테이블 상태는 비어있음 (occupied=false)으로 설정한다.
- 주문 테이블 관리
  - 주문 테이블 상태를 비어있지 않음으로 변경한다.
    - [ ] 주문 테이블이 존재해야 한다.
  - 주문 테이블 상태를 비어있음으로 변경한다.
    - [ ] 주문 테이블이 존재해야 한다.
    - [ ] 주문 상태가 완료(COMPLETED)인 주문 테이블만 비어있음으로 변경할 수 있다.
  - 주문 테이블의 손님수 변경
    - [ ] 주문 테이블이 존재해야 한다.
    - [ ] 주문 테이블의 손님수는 0명 이상이어야 한다.
    - [ ] 사용중인(occupied=true) 테이블의 손님 수만 변경할 수 있다/
- [ ] 상품을 조회한다.
