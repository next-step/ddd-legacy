# 키친포스

## 퀵 스타트

```sh
cd docker
docker compose -p kitchenpos up -d
```

## 요구 사항

- 치킨 가게에서 메뉴와 주문을 관리할 수 있는 pos 시스템을 구현한다.
- 상품
    - [ ]  가격, 이름을 가진 상품을 등록할 수 있다.
        - [ ]  상품의 가격은 비어있지 않고, 0원 이상이야 한다.
        - [ ]  상품의 이름은 비어있지 않고, purgomalum(외부서비스)를 통해 부적절한 단어 포함여부를 검증되어야 한다.
        - [ ]  상품 id는 중복되면 안된다.

    - [ ]  상품의 가격을 수정할 수 있다.
        - [ ]  상품의 가격은 비어있지 않고, 0원 이상이야 한다.
        - [ ]  이미 등록된 상품만 수정이 가능하다.
        - [ ]  상품이 포함된 모든 메뉴를 조회하고, 각 메뉴별로 메뉴의 가격이 메뉴에 포함된 모든 상품의 가격의 합보다 클 경우 메뉴의 상태를 비활성화 한다.

    - [ ]  등록된 상품 목록을 조회 할 수 있다.

- 메뉴그룹
    - [ ]  이름을 가진 메뉴 그룹을 등록할 수 있다.
        - [ ]  메뉴그룹의 이름은 비어있지 않아야 한다.
        - [ ]  메뉴그룹의 id는 중복되면 안된다.

    - [ ]  등록된 메뉴 그룹 목록을 조회 할 수 있다.

- 메뉴
    - [ ]  가격, 노출여부, 이름, 메뉴그룹 정보를 가진 메뉴를 등록 할 수 있다.
        - [ ]  메뉴를 등록하기 위해서는 메뉴그룹이 우선 등록되어 있어야한다.
        - [ ]  메뉴의 가격은 비어있지 않고, 0원 이상이야 한다.
        - [ ]  메뉴는 요청된 메뉴구성 상품들과 함께 등록이 된다.
        - [ ]  요청된 메뉴구성 상품들은 필수로 존재해야한다.
        - [ ]  요청된 메뉴구성 상품들의 상품은 모두 이미 존재해야한다.
        - [ ]  요청된 메뉴구성 상품들의 갯수와 이미 등록된 상품의 갯수는 동일해야 한다.
        - [ ]  요청된 메뉴구성 상품들 중 각각의 상품의 수량은 0개 이상이어야 한다.
        - [ ]  메뉴의 가격이 메뉴를 구성하는 상품들의 총 가격보다 높으면 안된다.
        - [ ]  메뉴 id는 중복되면 안된다.
        - [ ]  메뉴이름은 purgomalum(외부서비스)를 통해 부적절한 단어 포함여부를 검증한다.

    - [ ]  메뉴의 가격을 수정할 수 있다.
        - [ ]  수정하려는 메뉴의 가격은 비어있지 않고, 0원 이상이야 한다.
        - [ ]  이미 등록된 메뉴만 수정이 가능하다.
        - [ ]  수정하려는 메뉴의 가격이 메뉴를 구성하는 상품들의 총 가격보다 높으면 안된다.

    - [ ]  메뉴의 상태는 활성화, 비활성화로 구분된다.
    - [ ]  메뉴의 상태를 비활성화 -> 활성화로 수정 할 수 있다.
        - [ ]  이미 등록된 메뉴만 활성화가 가능하다.
        - [ ]  활성화하려는 메뉴의 가격이 메뉴를 구성하는 상품들의 총 가격보다 높으면 안된다.
    - [ ]  메뉴의 상태를 활성화 -> 비활성화로 수정 할 수 있다.
        - [ ] 이미 등록된 메뉴만 비활성화가 가능하다.
    - [ ]  등록된 메뉴 목록을 조회 할 수 있다.

- 주문 테이블
    - [ ]  이름, 인원수, 점유여부의 정보를 가진 주문 테이블을 등록 할 수 있다.
        - [ ]  주문테이블의 이름은 비어있지 않아야 한다.
        - [ ]  주문테이블의 id는 중복되면 안된다.
        - [ ]  최초엔 인원수는 0명, 비점유 상태의 테이블이 등록된다.
    - [ ]  주문테이블의 점유여부를 변경할 수 있다.(비점유 -> 점유)
        - [ ]  이미 등록된 주문테이블만 점유 상태로 변경할 수 있다.
    - [ ]  주문테이블의 점유여부를 변경할 수 있다.(점유 -> 비점유)
        - [ ]  이미 등록된 주문테이블만 비점유 상태로 변경할 수 있다.
        - [ ]  주문이 완료된 테이블의 상태만 변경이 가능하다.
        - [ ]  비점유 상태의 인원수는 0명이 된다.
    - [ ]  주문테이블의 인원수를 변경할 수 있다.
        - [ ]  변경요청한 인원수는 0명 이상이어야 한다.
        - [ ]  이미 등록된 주문테이블만 인원수 변경이 가능하다.
        - [ ]  이미 점유된 주문테이블만 인원수 변경이 가능하다.
    - [ ]  등록된 주문테이블 목록을 조회 할 수 있다.
- 주문
    - [ ] 주문타입, 주문상태, 주문시간, 배달주소, 주문 테이블정보를 가진 주문을 등록할 수 있다.
        - [ ] 	주문은 타입에 따라 3가지 종류로 나뉜다. (배달, 포장, 먹고가기)
        - [ ] 	주문시 주문타입은 필수이다.
        - [ ] 	주문은 상태에 따라 5가지로 나뉜다. (대기, 수락, 조리완료, 배달중, 배달완료, 주문완료)
        - [ ]   주문 타입에 따라 아래와 같은 상태 플로우를 가진다.
            - [ ]   배달: 대기 -> 수락 -> 조리완료 -> 배달중 -> 배달완료 -> 주문완료
            - [ ]   포장: 대기 -> 수락 -> 조리완료 -> 주문완료
            - [ ]   먹고가기: 대기 -> 수락 -> 조리완료 -> 주문완료
        - [ ] 	주문 등록시 최소 1개 이상의 주문요청항목이 있어야 한다.
        - [ ]   요청된 주문요청항목들의 갯수와 이미 등록된 메뉴의 갯수가 동일해야 한다.
        - [ ] 	주문 타입이 '먹고가기'가 아닌경우 주문요청항목의 수량이 음수면 안된다.
        - [ ] 	등록된 메뉴만 주문에 등록 할 수 있다.
        - [ ] 	활성화된 메뉴만 주문에 등록 할 수 있다.
        - [ ] 	메뉴의 가격과 주문요청항목들의 가격은 일치해야 한다.
        - [ ]   주문 id는 중복되면 안된다.
        - [ ]   최초 등록시 상태는 대기, 주문시간은 현재로 등록된다.

        - [ ] 	주문타입이 '배달'인 경우 배달주소값이 있어야한다.
        - [ ] 	주문타입이 '먹고가기'인 경우 점유된 주문테이블의 정보가 있어야한다.

    - [ ] 주문상태를 수락 으로 변경할 수 있다.
        - [ ] 등록된 주문이 대기 상태인 경우 변경할 수 있다.
        - [ ] 주문 타입이 배달인 경우 주문정보를 라이더스서비스(외부서비스)에 전달한다.

    - [ ] 주문상태를 조리완료 으로 변경할 수 있다.
        - [ ] 등록된 주문이 수락 상태인 경우 변경할 수 있다.

    - [ ] 주문상태를 배달중 으로 변경할 수 있다.
        - [ ] 등록된 주문이 조리완료 상태인 경우 변경할 수 있다.
        - [ ] 등록된 주문의 타입이 배달이어야 한다.

    - [ ] 주문상태를 배달완료 으로 변경할 수 있다.
        - [ ] 등록된 주문이 배달중 상태인 경우 변경할 수 있다.
        - [ ] 등록된 주문의 타입이 배달이어야 한다.

    - [ ] 주문상태를 주문완료 으로 변경할 수 있다.
        - [ ] 등록된 주문이 아래와 같은 경우 변경할 수 있다.
            - [ ] 주문타입: 배달, 주문상태: 배달중
            - [ ] 주문타입: 포장, 주문상태: 조리완료
            - [ ] 주문타입: 먹고가기, 주문상태: 조리완료
        - [ ] 주문타입이 먹고가기 일때, 연결된 주문테이블의 완료되지 않은 주문이 더 이상 없는 경우 테이블의 상태를 초기화 한다. (인원수: 0명, 상태: 비점유)

    - [ ] 등록된 주문 목록을 조회 할 수 있다.
