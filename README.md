# 키친포스

## 퀵 스타트

```sh
cd docker
docker compose -p kitchenpos up -d
```

## 요구 사항
음식점의 주문 시스템을 구현한다.

### 상품(product)
하나의 완성된 음식을 상품이라 부른다
- [ ] 상품은 상품명, 가격을 가진다
  - [ ] 상품명, 가격은 필수 입력 항목이다
  - [ ] 가격은 0원 이상이어야 한다
  - [ ] 상품명은 비속어가 있으면 입력할 수 없다
- [ ] 상품의 가격을 수정할 수 있다
  
### 메뉴(menu)
- [ ] 단일 또는 여러 상품을 조합하여 메뉴를 만들 수 있다
  - [ ] 각 메뉴를 구성하는 상품과 그 수량을 선택할 수 있다
- [ ] 메뉴는 메뉴명, 가격, 메뉴 노출 여부(노출 O/ 노출 X)를 가진다
  - [ ] 메뉴명, 가격, 메뉴 노출 여부는 필수 입력 항목이다
  - [ ] 메뉴명은 비속어가 있으면 입력할 수 없다
  - [ ] 메뉴의 가격은 0원 이상이어야 한다
- [ ] 메뉴는 하나의 메뉴 그룹을 가진다
- [ ] 메뉴의 가격, 노출 여부를 수정할 수 있다
  - [ ] 메뉴의 가격을 변경하거나, 메뉴의 노출 여부를 O로 변경할 때, 
여러 상품을 조합하여 만든 메뉴의 가격은 해당 상품들의 가격 합을 초과해서는 안된다
    
### 메뉴 그룹(menu_group)
- [ ] 메뉴 그룹명은 필수 입력 항목이다

### 주문 테이블(order_table)
매장 내 취식(EAT_IN)할 경우, 테이블의 주문 정보를 관리한다
- [ ] 테이블에 이름을 지정할 수 있다
  - [ ] 테이블 이름은 필수 입력 항목이다
- [ ] 테이블에 앉아있는 손님의 수를 확인할 수 있다
  - [ ] 손님의 수는 0명 이상이어야 한다
- [ ] 테이블에 현재 손님이 있음/없음 여부를 알 수 있다
- [ ] 테이블의 앉아있는 손님의 수, 손님 여부를 수정할 수 있다
  - [ ] 손님의 수를 수정할 때, 테이블의 손님 여부가 없음이면 수정할 수 없다
- 테이블 정리의 경우
  - [ ] 주문 상태가 완료가 아니면 정리할 수 없다
  - [ ] 손님의 수 0명, 손님여부 없음으로 수정한다

### 주문(orders)
- [ ] 주문의 종류는 배달(DELIVERY), 테이크아웃(TAKEOUT), 매장 내 취식(EAT_IN)으로 구분 값을 가진다
- [ ] 주문의 상태는 대기(WAITING), 주문 수락(ACCEPTED), SERVED(음식 제공됨), 배달 중(DELIVERING), 배달완료(DELIVERED), 주문완료(COMPLETED)
으로 구분 값을 가진다
- [ ] 주문은 주문이 생성된 일시를 가진다

#### 1) 주문 생성
  - [ ] 메뉴는 노출 여부가 'O'인 경우만 주문 가능하다
  - [ ] 신규 주문 생성 시, 주문 상태는 대기(WAITING)이다 
  - [ ] 주문 종류가 배달인 경우, 배달 주소가 입력되어야 한다
  - 매장 내 취식(EAT_IN)인 경우 
    - [ ] 어떤 주문 테이블에서 주문되었는지 알 수 있어야 한다
    - [ ] 주문 테이블은 손님 여부가 있음이어야 한다.
  - [ ] 배달(DELIVERY)의 경우, 배달 주소는 필수 입력 값이다

#### 2) 주문 수락
- [ ] 주문 상태가 대기(WAITING)이어야 한다
- [ ] 주문 상태가 배달(DELIVERY)인 경우, 라이더에게 주문 정보(주문 총액, 배달 주소)를 제공하여 배달하도록 한다
- [ ] 모든 작업 완료된 후, 주문 상태를 주문 수락(ACCEPTED)으로 변경한다

#### 3) 음식 제공
- [ ] 주문 상태가 주문 수락(ACCEPTED)이어야 한다
- [ ] 주문 상태를 음식 제공됨(SERVED)으로 변경한다

#### 4) 배달 
- 4)-1 배달 시작
  - [ ] 주문 종류가 배달(DELIVERY)이어야 한다
  - [ ] 주문 상태가 음식 제공됨(SERVED)이면 안된다
  - [ ] 주문 상태를 배달 중(DELIVERING)으로 변경한다
- 4)-2 배달 완료
  - [ ] 주문 상태를 배달 중(DELIVERING)이어야 한다
  - [ ] 주문 상태를 배달완료(DELIVERED)으로 변경한다

#### 5) 주문 완료
- [ ] 주문 종류가 배달(DELIVERY)의 경우, 주문 상태는 배달완료(DELIVERED)이어야 한다
- [ ] 주문 종류가 테이크아웃(TAKEOUT), 매장 내 취식(EAT_IN)인 경우는 주문 상태는 음식 제공됨(SERVED)이어야 한다
- [ ] 주문 상태를 주문완료(COMPLETED)로 변경한다
- 매장 내 취식(EAT_IN)의 경우
  - [ ] 해당 주문 테이블에 모든 주문이 완료됐는지 확인한다
  - [ ] 해당 주문 테이블의 손님의 수를 0, 손님 여부를 X로 변경한다

### 주문 상세(order_line_item)
- [ ] 하나의 주문에 포함된 메뉴와 각 메뉴의 수량을 관리한다
- [ ] 주문 생성 시 매장 내 취식(EAT_IN)이 아닌 경우, 주문 상세에 포함된 각 메뉴의 수량이 0 이상이어야 한다
