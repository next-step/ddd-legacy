## 요구사항



### 데이터 모델링 분석

~~~
 ┌──────────────┐(1)(N)┌──────────────┐(N)(1)┌──────────────┐
 │   product    │◄─────│ menu_product │─────►│     menu     │
 └──────────────┘      └──────────────┘      └──────────────┘
                                              ▲ (1)   ▲ (1)
                                              │       │ (N)
                                              │   ┌──────────────┐
                                     	      │   │ menu_group   │
                                     	      │   └──────────────┘
                                              │(N)
 ┌──────────────┐(1)(N)┌──────────────┐(1)(N)┌─────────────────┐
 │  order_table │◄─────│    orders    │─────►│ order_line_item │
 └──────────────┘      └──────────────┘      └─────────────────┘
~~~

| 테이블                        | 설명                                                         | 비고                                                         |
|----------------------------| ------------------------------------------------------------ | ------------------------------------------------------------ |
| product<br>(상품)            | 팔기 위해 생산할 수 있는 개별 품목 (예: 후라이드, 양념치킨)  | 가격정보가 있음                                              |
| menu<br>(메뉴)               | 실제 판매를 위해 메뉴판에 올려놓은 상품                      |                                                              |
| menu_group<br>(메뉴 그룹)      | 여러 menu들의 그룹                                           |                                                              |
| menu_product<br>(구성 상품)    | menu와 product를 연결 (예: 나혼자 후라이드 메뉴 <- 샐러드 Product + 후라이드치킨 Product) |                                                              |
|                            |                                                              |                                                              |
| orders<br>(주문)             | 주문 정보 (예: 21년7월27일 진행중인 배달 건, 21년 7월 26일 7번 테이블 매장 식사 완료 ) | 주문 진행 상태 (WAITING / COMPLETED)<br />주문 타입 (EAT_IN / DELIVERY) |
| order_line_item<br>(주문 항목) | 주문된 메뉴 항목과 수량 (예: 특정 주문에서 후라이드치킨 1개 포함) |                                                              |
| order_table<br>(매장 테이블)    | 매장 테이블 정보 (예: 1번 테이블)                            | 1~8번 테이블 존재                                            |



### 요구사항 상세 분석

- 치킨집 프로그램을 구현한다.

- 사장님

    - 사장님은 `메뉴`를 관리할 수 있어야 한다.
        - [ ] 사장님은 `메뉴`를 생성할 수 있다.
          - [ ] 가격은 1원 이상이어야 한다.
          - [ ] 생성할 `메뉴`는 이미 생성된 `메뉴 그룹`에 속해야 한다.
          - [ ] `메뉴`는 하나 이상의 `상품`을 포함해야 한다.
          - [ ] `메뉴`는 `구성 상품`으로 등록된 `상품`만 포함해야 한다.
          - [ ] 각 `메뉴`의 `구성 상품`은 각각 1개 이상의 수량이어야 한다.
          - [ ] `메뉴`의 가격은 `구성 상품` 가격의 총합을 넘을 수 없다.
          - [ ] `메뉴` 이름에 비속어가 포함되면 안된다.
          
        - [ ] 사장님은 `메뉴`의 가격을 변경할 수 있다.
          - [ ] 변경될 가격이 1원 이상이어야 한다.
          - [ ] 변경될 `메뉴`의 가격은 `구성 상품` 가격의 합을 넘을 수 없다.
        - [ ] 사장님은 `메뉴`를 표시할 수 있다.
          - [ ] `메뉴`의 가격이 `구성 상품` 가격의 합을 초과하면 표시할 수 없다.
        - [ ] 사장님은 `메뉴`를 숨길 수 있다.
        - [ ] 사장님은 모든 `메뉴` 목록을 조회할 수 있다.

    - 사장님은 `메뉴 그룹`을 관리할 수 있어야 한다.
        - [ ] 사장님은 `메뉴 그룹`을 생성할 수 있다.
        - [ ] 사장님은 모든 `메뉴 그룹` 목록을 조회할 수 있다.

    - 사장님은 `주문`을 관리할 수 있어야 한다.
        - [ ] 사장님은 고객의 `주문`을 접수할 수 있다.
          - [ ] 대기 상태의 `주문`만 접수할 수 있다.
          - [ ] `배달 주문`의 경우, 기사에게 배달 요청해야 한다.
        - [ ] 사장님은 조리가 완료된 `주문`을 제공할 수 있어야 한다.
          - [ ] 접수 상태의 `주문`만 제공할 수 있다.
        - [ ] 사장님은 `배달 주문`이 시작되었음을 기록할 수 있어야 한다.
          - [ ] 배달 `주문`만 배달 시작할 수 있다.
          - [ ] 제공된 상태의 `주문`만 배달 시작할 수 있다.
        - [ ] 사장님은 `배달 주문`이 완료되었음을 기록할 수 있어야 한다.
          - [ ] 배달 중 상태의 `주문`만 배달 완료할 수 있다.
        - [ ] 사장님은 `주문`이 최종적으로 완료되었음을 기록할 수 있어야 한다.
          - [ ] `매장 주문`, `포장 주문`은 제공된 상태의 `주문`만 완료할 수 있다.
          - [ ] `배달 주문`은 배달 완료상태의 `주문`만 완료할 수 있다.
          - [ ] `매장 주문`이 완료되면 `매장 테이블` 상태를 미사용으로 바꾸고 인원 수를 0으로 설정한다.
        - [ ] 사장님은 모든 `주문`을 조회할 수 있어야 한다.

    - 사장님은 `매장 테이블`을 관리할 수 있어야 한다.
        - [ ] 사장님은 새로운 `매장 테이블`을 추가할 수 있다.
          - [ ] `매장 테이블`의 기본 상태는 미사용, 인원수 0명이다.
        - [ ] 사장님은 `매장 테이블`을 청소할 수 있다.
          - [ ] `주문` 이 완료된 `매장 테이블`만 청소할 수 있다.
          - [ ] 청소된 `매장 테이블`의 상태는 미사용, 인원수 0명이다.
        - [ ] 사장님은 특정 `매장 테이블`의 인원 수를 변경할 수 있다.
          - [ ] 수정된 인원 수는 1명 이상이어야 한다.
          - [ ] 사전에 등록되지 않은 `매장 테이블`은 인원 수를 변경할 수 없다.
          - [ ] 사용중인 `매장 테이블`만 인원 수를 변경할 수 있다. 
        - [ ] 사장님은 모든 `매장 테이블` 목록을 조회할 수 있다.

    - 사장님은 `상품`을 관리할 수 있어야 한다.
        - [ ] 사장님은 새로운 `상품`을 생성할 수 있다.
          - [ ] `상품` 가격은 1원 이상이어야 한다.
          - [ ] `상품` 이름은 필수적으로 포함되어야 한다.
          - [ ] `상품` 이름에 비속어가 포함되면 안된다.
        - [ ] 사장님은 특정 `상품`의 가격을 변경할 수 있다.
          - [ ] 변경될 가격은 1원 이상이어야 한다.
          - [ ] 가격 변경 `상품`이 포함된 `메뉴`의 총가격이 변경의 영향으로 더 커진다면, 해당 `메뉴`를 숨김처리 한다.
        - [ ] 사장님은 등록된 모든 `상품` 목록을 조회할 수 있다.



- 고객

    - `주문`
        - [ ] 고객은 `메뉴`를 선택해 `주문`할 수 있어야 한다.
          - [ ] 고객은 주문 타입을 선택해야 한다. (매장, 배달, 포장)
          - [ ] 고객은 `주문 항목`을 1개 이상 추가해야 한다.
          - [ ] 고객은 `매장 주문`이 아닌 경우, 각 `주문 항목`의 수량을 1개 이상 선택해야 한다.
          - [ ] 고객은 표시 상태의 `메뉴`만 주문할 수 있다.
          - [ ] `메뉴`의 가격과 `주문 항목`의 총 가격은 같아야 한다.
          - [ ] `주문` 최초 생성시 상태는 대기여야 한다.
          - [ ] `배달 주문`이면 배달 주소를 입력해야 한다.
          - [ ] `매장 주문`이면 미사용 상태인 `매장 테이블`을 선택해야 한다.
    - 테이블
        - [ ] 고객은 특정 `매장 테이블`에 착석할 수 있어야 한다.
          - [ ] 고객이 착석한 `매장 테이블`은 사용중인 상태로 변경된다.

1. 매장 주문 (EAT_IN)

~~~mermaid
sequenceDiagram
    participant 고객
    participant 시스템
    participant 사장님

    고객 ->> 시스템: (1) 주문 생성 요청
    시스템 ->> 고객: 주문 생성 완료 (WAITING)

    사장님 ->> 시스템: (2) 주문 접수 요청
    시스템 ->> 사장님: 주문 상태 변경 (ACCEPTED)

    사장님 ->> 시스템: (3) 조리 완료 처리
    시스템 ->> 사장님: 주문 상태 변경 (SERVED)

    고객 ->> 시스템: (4) 고객이 식사
    사장님 ->> 시스템: (5) 주문 완료 처리 (COMPLETED)

    시스템 ->> 시스템: 테이블 상태 변경 (미사용)
~~~





2. 배달 주문 (DELIVERY)

~~~mermaid
sequenceDiagram
    participant 고객
    participant 시스템
    participant 사장님
    participant 배달 서비스

    고객 ->> 시스템: (1) 주문 생성 요청 (배달 주문)
    시스템 ->> 고객: 주문 생성 완료 (WAITING)

    사장님 ->> 시스템: (2) 주문 접수 요청
    시스템 ->> 사장님: 주문 상태 변경 (ACCEPTED)
    시스템 ->> 배달 서비스: 배달 요청 수행

    사장님 ->> 시스템: (3) 조리 완료 처리
    시스템 ->> 사장님: 주문 상태 변경 (SERVED)

    사장님 ->> 시스템: (4) 배달 시작 요청
    시스템 ->> 사장님: 주문 상태 변경 (DELIVERING)

    배달 서비스 ->> 시스템: (5) 배달 완료 알림
    시스템 ->> 사장님: 주문 상태 변경 (DELIVERED)

    고객 ->> 시스템: (6) 고객이 수령 확인
    사장님 ->> 시스템: (7) 주문 완료 처리 (COMPLETED)
~~~

    사장님 ->> 시스템: (3) 조리 완료 처리
    시스템 ->> 사장님: 주문 상태 변경 (SERVED)
